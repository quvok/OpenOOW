# План достижения OpenOOW 1.0

Дата аудита: 2026-11-15  
Базовый commit: 1ed1df3ffa54c9a1d3a8804672263f31143bc46f  
Требования: [Техническая спецификация 1.0](TECHNICAL_SPECIFICATION.md)

Этот документ — release gate. Номер 1.0 присваивается только после выполнения обязательных критериев и успешной проверки сборки, тестов и публикации. Наличие прототипа не считается завершением модуля.

## Исходный аудит репозитория

Проверка выполнена по дереву `main`, исходникам, тестам, README и архитектурной документации.

| Требование | Наличие в базовой версии | Что необходимо до 1.0 |

| React + TypeScript + Vite | Есть | Проверить production и мобильную адаптацию |
| Simulation Core, fixed step | Есть | Сквозная воспроизводимость сценариев и единый state engine |
| Ship Dynamics | Частичная модель | Инерция, реверс, движитель, боковой снос, поворотные характеристики и ограничения модели |

| Offline | Не подтверждено | PWA/offline стратегия и тестирование без сети |

## Обязательные релизные ворота

- [ ] Все функциональные модули из спецификации представлены работающими функциями, а не заглушками.
- [ ] Ядро не зависит от React, DOM или UI.
- [ ] Единицы, системы координат, допущения и ограничения документированы.
- [ ] CPA/TCPA и ключевые навигационные расчёты имеют тесты на граничные случаи.
- [ ] Воспроизводимый фиксированный шаг используется всеми динамическими подсистемами.
- [ ] Сценарии можно завершить и получить понятный разбор.
- [ ] Данные и прогресс сохраняются локально; основные функции доступны офлайн.
- [ ] UI проверен на ПК и мобильных устройствах.
- [ ] Windows приложение собирается и запускается.
- [ ] Vitest, TypeScript build, Playwright и Pages deployment проходят.
- [ ] README, архитектура, ограничения и инструкция запуска соответствуют фактическому состоянию.
- [ ] В репозитории нет ложных заявлений о сертификации или полной ENC/ECDIS функциональности.

## Последовательность работ

1. Инвентаризация ядра и устранение архитектурных дефектов.
2. Environment Model и интеграция среды с динамикой и датчиками.
3. Ship Dynamics / Ship Handling: движитель, инерция, реверс, поворот, дрейф.
4. Radar: режимы отображения, настройки, clutter и измерительная модель.
5. ARPA: маневрирующие цели, качество сопровождения, тестирование и тревоги.
6. COLREG-72: аудит покрытия и проверка сценариев с контекстом.
7. 3D Bridge на Three.js.
8. ECDIS: продолжение карты и маршрутизации без завышения статуса ENC.
9. Emergency Training.
10. Examination и локальное сохранение прогресса через IndexedDB.
11. Адаптивный интерфейс, offline/PWA и Playwright.
12. Tauri / Windows packaging.
13. Полная регрессия, документация, release candidate и только затем v1.0.0.

## Правило статусов

- **Implemented** — функция реально работает и подключена к приложению.
- **Partial** — часть поведения реализована; ограничения перечислены.
- **Not implemented** — отсутствует либо является только макетом.
- **Verified** — дополнительно покрыта тестами/сквозной проверкой.

Изменение номера версии не переводит пункт в Implemented или Verified.
